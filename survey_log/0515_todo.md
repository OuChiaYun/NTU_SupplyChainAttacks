> In general, software supply chain attacks aim to inject malicious code into a software product. Frequently, attackers tamper with the end product of a given vendor such that it carries a valid digital signature, as it is signed by the respective vendor, and may be obtained by end-users through trusted distribution channels, e.g. download or update sites. ([springer][1])

**Supply chain attacks** target the *distribution pipeline*, not the application code.
Documented across every major ecosystem:

- **npm** — event-stream (2018), axios (2026), TanStack (2026)
- **PyPI** — typosquatting and dependency confusion campaigns
- **Maven, RubyGems, cargo** — documented backdoor attempts

### TODO2-2
分析了可能使用supply chain attacks 的19 種手法
> 此論文整理並分析了 19 種 Software Supply Chain（SSC）攻擊手法，其中包含 6 種近年研究中新提出或較新的攻擊類型。作者是透過文獻與真實事件整理出 taxonomy，用來對應攻擊、緩解措施與風險評估策略。([sciencedirect][5])

| 類別                       | 攻擊手法                                  | 說明                                                                                                             |
| ------------------------ | ------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| 名稱偽裝攻擊                   | Typosquatting                         | 攻擊者註冊與知名套件名稱很像的惡意套件，例如拼字錯誤、少一個字母、多一個字母，讓開發者誤裝。                                                                 |
| 名稱偽裝攻擊                   | Combosquatting                        | 在合法套件名稱前後加上 prefix/suffix，讓套件看起來像官方延伸版本，例如 `xxx-dev`、`xxx2`。                                                   |
| 套件內容攻擊                   | Code Injection                        | 攻擊者把惡意程式碼注入到合法軟體或套件中，通常只改很小一段，因此不容易被人工審查發現。                                                                    |
| 維護風險攻擊                   | Exploiting Unmaintained Legacy Code   | 利用長期沒有人維護的舊套件或遺留程式碼，因為漏洞沒被修補，進而被當成供應鏈攻擊入口。                                                                     |
| 權限接管攻擊                   | Ownership Transfer / Package Takeover | 攻擊者取得套件維護權限，之後發布含惡意程式碼的新版本。event-stream 事件就是典型案例。                          |
| 帳號接管攻擊                   | Account Takeover                      | 攻擊者盜用 maintainer 或 developer 帳號，例如透過弱密碼、憑證外洩或社交工程，接著發布惡意套件。                                                    |
| 中繼資料攻擊                   | Metadata Manipulation                 | 操弄 Git metadata、reference 或 repository 狀態，使開發者看到錯誤版本，可能導致安全修補被漏掉或錯誤程式碼被合併。                                     |
| 簽章與憑證攻擊                  | Certificate Theft                     | 竊取開發者或廠商的簽章憑證，用合法簽章包裝惡意更新，使惡意軟體看起來可信。                                                                          |
| 簽章與憑證攻擊                  | Exploitation of Signature System      | 濫用或繞過簽章驗證機制，甚至在簽章流程前注入惡意內容，讓惡意產物仍然帶有有效簽章。                                                                      |
| Registry / Dependency 攻擊 | Dependency Confusion                  | 當專案同時使用 private registry 與 public registry 時，攻擊者在 public registry 發布同名套件，誘使 package manager 下載錯誤來源。 |
| Registry / Naming 攻擊     | Case Sensitivity Confusion            | 利用大小寫差異註冊惡意套件，例如某些 registry 或工具鏈對大小寫處理不一致，造成開發者或系統誤裝。                                    |
| Registry Mirror 攻擊       | Ghost Package Attack in Mirrors       | 利用 registry mirror 的同步限制或狀態不一致，讓 mirror 中出現原始 registry 不存在或難以追蹤的套件。                                |
| Registry Mirror 攻擊       | Mirror Package Override               | 在 registry 與 mirror 同步時，攻擊者讓上游 registry 中的惡意套件覆蓋 mirror-only 的內部套件名稱。                             |
| Registry Redirection 攻擊  | Package Redirection Hijacking         | 攻擊者操弄套件重新導向或上游 registry 行為，使使用者下載到攻擊者控制的套件。                                                         |
| AI 相關新型攻擊                | ChatGPT Hallucination Hijacking       | 攻擊者註冊 LLM 可能「幻覺產生」的不存在套件名稱；當開發者照著 AI 建議安裝時，就可能下載到惡意套件。


[5]: https://www.sciencedirect.com/science/article/pii/S2214212625003606
